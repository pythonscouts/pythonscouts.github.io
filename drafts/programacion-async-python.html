Cómo crear programas asíncronos en Python: la forma correcta

Leodanis Pozo Ramos
30 oct. 2026
python

La programación asíncrona permite suspender y reanudar tareas. En Python, la librería asyncio implementa un bucle de eventos que permite para ejecutar varias tareas concurrentemente.

Como complemento, Python incluye las palabras clave async y await para definir y esperar funciones asíncronas, respectivamente.

Parece simple, pero este set de herramientas de Python puede ser fácil de malinterpretar. Una función definida con async puede parecer asíncrona, y asyncio.run() inicia un bucle de eventos. Ninguno de esos hechos garantiza que el programa realice varias operaciones de forma concurrente.

En esta guía aprenderás qué hace falta para que las tareas cedan el control y compartan el tiempo de espera.

Una función asíncrona no se ejecuta al llamarla

Definir una función con async def crea una función corrutina. Llamar a esa función no ejecuta su cuerpo de inmediato. En su lugar, la llamada devuelve un objeto corrutina:

Python REPL
>>> async def fetch_data():
...     return 42
...

>>> coroutine = fetch_data()
>>> coroutine
<coroutine object fetch_data at 0x...>
>>> coroutine.close()

Al llamar a fetch_data(), obtienes un objeto corrutina. El cuerpo de la función todavía no se ejecuta. En este ejemplo, coroutine.close() cierra el objeto sin ejecutarlo para evitar una advertencia al salir del entorno interactivo de Python (Read-Eval-Print Loop, REPL por sus siglas en inglés).

Para ejecutar una corrutina, debes esperarla desde otra función asíncrona con await o pasarla a asyncio.run().

El bucle de eventos asíncronos

La función asyncio.run() es fundamental en la programación asíncrona en Python. Esta función inicia el bucle de eventos y ejecuta la corrutina desde un contexto síncrono.

Como continuación del ejemplo anterior, puedes pasar la corrutina directamente a asyncio.run() para ejecutarla y obtener el valor que devuelve:

Python REPL
>>> import asyncio

>>> async def fetch_data():
...     return 42
...

>>> asyncio.run(fetch_data())
42

La llamada a asyncio.run() espera a que la corrutina termine y devuelve su resultado. En este caso, el resultado es 42.

El bucle de eventos no es un motor mágico de ejecución paralela. Ejecuta una pieza de código Python a la vez. Cuando el bucle de eventos está ejecutando una corrutina, ninguna otra puede avanzar hasta que la actual se suspenda con await.

El proceso funciona así:

  1. asyncio.run() pone en marcha el bucle de eventos y ejecuta la corrutina principal.
  2. La corrutina principal llega a un await y espera otra corrutina. Si esta termina enseguida, el programa continúa.
  3. Si la corrutina tiene que esperar, por ejemplo, una respuesta de la red, en ese momento se pausa y el control vuelve al bucle de eventos.
  4. El bucle de eventos recibe el control y puede avanzar otras corrutinas que estén listas para ejecutarse.
  5. Cuando termina la espera de la corrutina pausada, la tarea continúa desde donde se pausó hasta completar su ejecución.

Al terminar la corrutina principal, asyncio.run() devuelve su resultado y cierra el bucle de eventos. Si la corrutina no devuelve un valor, el resultado es None.

La espera secuencial no es concurrencia

Considera dos operaciones llamadas A y B que demoran un segundo en ejecutarse cada una:

Python - sequential_awaits.py
import asyncio
import time

async def fetch(name, delay):
    print(f"{name}: iniciada")
    await asyncio.sleep(delay)
    print(f"{name}: finalizada")
    return f"resultado de {name}"

async def main():
    start = time.perf_counter()
    await fetch("A", 1)
    await fetch("B", 1)
    sequential_time = time.perf_counter() - start
    print(f"Tiempo secuencial: {sequential_time:.1f} segundos")

asyncio.run(main())

La operación B no comienza hasta que la operación A ha terminado. Puedes comprobarlo observando la salida del script y el tiempo total de ejecución con el siguiente comando:

Terminal
$ python sequential_awaits.py
A: iniciada
A: finalizada
B: iniciada
B: finalizada
Tiempo secuencial: 2.0 segundos

Tu programa tarda unos dos segundos en ejecutarse porque espera a que termine la primera operación antes de iniciar la segunda. Aunque fetch() es asíncrona, estas dos llamadas se ejecutan secuencialmente.

La llamada await fetch("A", 1) ejecuta la operación, mientras el programa espera a que termine para continuar con la siguiente línea de código, es decir, la llamada a fetch("B", 1). Por sí sola, una espera con await no inicia otras operaciones al mismo tiempo.

Crear tareas realmente concurrentes: el ingrediente que falta

Para que una programación en Python sea realmente concurrente, necesitas crear tareas que puedan ejecutarse de manera independiente, sin depender unas de otras. Estas tareas deben poder ejecutarse, pausarse y reanudarse, es decir, deben ser corutinas.

Luego, necesitas crear y lanzar estas tareas de manera asíncrona. Esto lo puedes hacer con TaskGroup y gather().

Uso de TaskGroup

La clase TaskGroup es un manejdor de contexto que se utiliza para la ejecución concurrente de un grupo de tareas asíncronas dentro de un bloque async with. Un grupo de tareas hace dos cosas importantes:

  1. Crea una tarea para cada corrutina que se pasa a group.create_task().
  2. Espera a todas las tareas antes de salir del bloque async with.

Veamos un ejemplo de cómo usar TaskGroup:

Python - taskgroup_example.py
import asyncio
import time

async def fetch(name, delay):
    print(f"{name}: iniciada")
    await asyncio.sleep(delay)
    print(f"{name}: finalizada")
    return f"resultado de {name}"

async def main():
    start = time.perf_counter()

    async with asyncio.TaskGroup() as group:
        group.create_task(fetch("A", 1))
        group.create_task(fetch("B", 1))

    elapsed = time.perf_counter() - start
    print(f"Tiempo transcurrido: {elapsed:.1f} segundos")

asyncio.run(main())

En este ejemplo, ambas tareas, A y B, se inician casi al mismo tiempo y se ejecutan de manera concurrente dentro del bloque async with.

Ejecuta el script con el siguiente comando:

Terminal
$ python taskgroup_example.py
A: iniciada
B: iniciada
A: finalizada
B: finalizada
Tiempo transcurrido: 1.0 segundos

El tiempo total es de aproximadamente un segundo porque las esperas de ambas tareas se solapan. Las tareas se ejecutan de forma concurrente dentro del grupo, que espera a que ambas finalicen antes de terminar y pasar a la siguiente instrucción del programa.

Uso de gather()

Para situaciones donde realmente solo necesitas recolectar resultados de varias corrutinas, gather() es una herramienta útil:

Python - gather_example.py
import asyncio
import time

async def fetch(name, delay):
    print(f"{name}: iniciada")
    await asyncio.sleep(delay)
    print(f"{name}: finalizada")
    return f"resultado de {name}"

async def main():
    start = time.perf_counter()
    await asyncio.gather(
        fetch("A", 1),
        fetch("B", 1),
    )
    elapsed = time.perf_counter() - start
    print(f"Tiempo transcurrido: {elapsed:.1f} segundos")

asyncio.run(main())

En este ejemplo, asyncio.gather() te permite ejecutar las tareas A y B de manera concurrente y esperar a que ambas finalicen antes de continuar.

Ejecuta el script con este comando:

Terminal
$ python gather_example.py
A: iniciada
B: iniciada
A: finalizada
B: finalizada
Tiempo transcurrido: 1.0 segundos

En la práctica, gather() es conveniente cuando tu objetivo principal es recolectar resultados. Devuelve los resultados en el mismo orden en que se proporcionaron los objetos que admiten await, aunque las tareas terminen en otro orden.

TaskGroup ofrece un control más estructurado sobre el ciclo de vida de las tareas. Las agrupa y espera a que todas terminen. Si una tarea lanza una excepción distinta de CancelledError, cancela las demás y luego propaga las excepciones en un grupo. Por eso suele ser una buena opción para código nuevo cuando las tareas deben gestionarse como una unidad.

El patrón esencial es el mismo en ambos casos: crear o recibir varias corrutinas, ponerlas en marcha como tareas y luego esperar a que todas terminen.

Uso de as_completed()

Mientras que gather() devuelve los resultados en el orden de entrada, as_completed() te permite procesarlos en el orden en que terminan las tareas. Esto es útil cuando quieres manejar los resultados tan pronto como estén disponibles.

Considera el siguiente ejemplo:

Python - as_completed_example.py
import asyncio

async def fetch(name, delay):
    print(f"{name}: iniciada")
    await asyncio.sleep(delay)
    return f"resultado de {name}"

async def main():
    tasks = [
        asyncio.create_task(fetch("A", 3)),
        asyncio.create_task(fetch("B", 1)),
        asyncio.create_task(fetch("C", 2)),
    ]

    for completed in asyncio.as_completed(tasks):
        result = await completed
        print(result)

asyncio.run(main())

Ejecuta el script con este comando:

Terminal
$ python as_completed_example.py
A: iniciada
B: iniciada
C: iniciada
resultado de B
resultado de C
resultado de A

En este ejemplo, la tarea B termina primero, luego la C y finalmente la A, y sus resultados se procesan en ese mismo orden.

Las llamadas bloqueantes impiden la concurrencia

El código asíncrono también depende del uso de operaciones no bloqueantes. Reemplazar una llamada síncrona con async def no hace que la llamada deje de bloquear.

Por ejemplo, time.sleep() bloquea el bucle de eventos completo:

Python - blocking_task.py
import asyncio
import time

async def bad_task(name):
    print(f"{name}: iniciada")
    time.sleep(1)  # Bloquea el bucle de eventos
    print(f"{name}: finalizada")

async def main():
    async with asyncio.TaskGroup() as group:
        group.create_task(bad_task("A"))
        group.create_task(bad_task("B"))

asyncio.run(main())

Aunque ambas tareas están listas para ejecutarse, la tarea B no puede avanzar mientras la tarea A está dentro de time.sleep(). El bucle de eventos queda atascado esperando a que la llamada bloqueante retorne.

Para las demostraciones, await asyncio.sleep() simula una espera no bloqueante. En aplicaciones reales, el mismo principio se aplica a las bibliotecas que usas: elige clientes de base de datos, clientes del protocolo de transferencia de hipertexto (HTTP), colas y operaciones de archivos compatibles con programación asíncrona cuando quieras que el bucle de eventos siga siendo receptivo.

Si una operación bloqueante es inevitable, puede que necesites moverla a un hilo o proceso de trabajo en lugar de ejecutarla directamente dentro del bucle de eventos.

Un modelo mental práctico

Una forma fiable de razonar sobre Python asíncrono es hacerte cuatro preguntas:

  1. ¿Cuál es la corrutina? Una llamada async def produce un objeto corrutina.
  2. ¿Quién la está ejecutando? La corrutina debe esperarse o iniciarse como tarea en un bucle de eventos.
  3. ¿Dónde puede ceder? Busca expresiones await que esperan operaciones incompletas y no bloqueantes.
  4. ¿Qué otro trabajo está listo? Sin otras tareas listas, ceder puede simplemente dejar el bucle de eventos inactivo. La concurrencia requiere múltiples tareas que puedan turnarse.

Este modelo también explica por qué una aplicación puede contener muchas funciones asíncronas y aun así comportarse de forma síncrona. Puede esperar cada operación una a una, realizar trabajo intensivo del procesador sin ceder, o llamar a funciones bloqueantes dentro de corrutinas.

Conclusión

La programación asíncrona en Python no consiste en añadir async a cada función ni en envolver un programa en asyncio.run(). Esas características establecen la maquinaria, pero no producen concurrencia de forma automática.

El código asíncrono funciona como se pretende cuando:

  • varias corrutinas se ponen en marcha como tareas
  • las tareas ceden en puntos await no bloqueantes
  • el bucle de eventos tiene otro trabajo listo para ejecutar
  • las operaciones bloqueantes se mantienen fuera del bucle de eventos

En resumen:

async def define una corrutina, asyncio.run() inicia el bucle de eventos, await brinda oportunidades para ceder y poner varias tareas en marcha crea el trabajo concurrente.

Una vez que esa distinción queda clara, el comportamiento de asyncio resulta mucho menos misterioso: el código sigue ejecutando una instrucción a la vez, pero varias tareas pueden solapar sus períodos de espera en lugar de hacer que el programa espere por cada operación de forma independiente.
